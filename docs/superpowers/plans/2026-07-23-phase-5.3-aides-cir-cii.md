# Phase 5.3 · Aides publiques, base CIR/CII annualisée (refonte Pilot)

> Document de plan. À valider avec Actemis avant implémentation.
> Cas d'exemple : projet France 2030 "Outil digital" de Releaf Carbon (dossier BPI 4175510).

## 1. Objectif

Permettre à Pilot de calculer la **base CIR et CII nette par année**, en tenant compte des aides publiques
(subventions + avances récupérables), selon la méthode de rattachement d'Actemis :

- **Lissage** du total des aides sur la durée du projet, quote-part imputée à chaque année.
- **Subvention** : déduite définitivement (jamais réintégrée).
- **Avance récupérable** : déduite pendant le projet, **réintégrée au rythme du remboursement**
  (remboursement indexé sur le CA du produit, donc incertain : à piloter sur le réel).
- **Base éligible** = les dépenses réelles du projet, saisies dans Pilot (postes annualisés).

Anti double comptage : une même dépense ne doit pas gonfler à la fois l'amortissement, la base CIR/CII,
et être comptée nette d'aide plusieurs fois.

## 2. Rappel du modèle actuel (Phases 5.1 / 5.2, livrées)

- Table `immobilisations` : libellé, montant, date_mise_en_service, durée, méthode, traitement, justification.
- Table `immobilisation_postes` : libellé, source (salaire/prestation/autre), source_ref, montant,
  credit_type (none/cir/cii), prestataire_agree, subvention.
- Montant amortissable effectif = somme des postes (sinon montant saisi).
- Base CIR/CII (statique) = Σ postes éligibles (montant − subvention), avec règle d'agrément pour les prestations.
- Amortissement prorata temporis, la dotation alimente `/api/ebe` (Compte de résultat).

**Ce qui manque pour la 5.3** : la dimension **annuelle** (postes par année), et un vrai objet **aide**
(subvention / avance) avec lissage et réintégration, à la place du simple champ `subvention` par poste.

## 3. Modèle de données cible

### 3.1 `immobilisation_postes` : ajouter l'année
- `annee INT` (année d'engagement de la dépense éligible).
- On retire la logique "subvention par poste" (remplacée par l'objet aide, §3.3) OU on la garde pour les
  petites subventions directes non-projet. À trancher : **recommandation = garder `subvention` pour un cas simple,
  mais les aides projet passent par la nouvelle table**.

### 3.2 `immobilisations` : période de projet
- `date_debut_projet DATE`, `date_fin_projet DATE` (nullable) : la fenêtre de rattachement pour le lissage.
  Distincte de `date_mise_en_service` (qui pilote l'amortissement).

### 3.3 Nouvelle table `immobilisation_aides`
| Colonne | Type | Rôle |
|---|---|---|
| id | UUID PK | |
| immobilisation_id | UUID FK cascade | |
| type | TEXT ('subvention' \| 'avance') | subvention = définitive ; avance = réintégrable |
| financeur | TEXT | ex. "État", "Région HDF" (info) |
| credit_cible | TEXT ('cir' \| 'cii') | quelle base l'aide réduit |
| montant | NUMERIC | montant total de l'aide |
| remboursement_debut | DATE (nullable) | avance : date de 1er remboursement (ex. 30/06/2029) |
| remboursement_montant_annuel | NUMERIC (nullable) | avance : montant remboursé par an (ex. 11 200) |
| notes | TEXT | infos libres (financeur, dossier BPI...) |
| created_at / updated_at | TIMESTAMPTZ | |

RLS allow-all (mono-locataire), comme les autres tables.

## 4. Calculs backend

### 4.1 Lissage d'une aide sur le projet
`quotePartAnnee(aide, annee)` = `aide.montant × (jours du projet dans l'année / durée totale projet en jours)`
sur `[date_debut_projet, date_fin_projet]`. (Même logique prorata-temporis que l'amortissement.)

### 4.2 Réintégration d'une avance
`reintegrationAnnee(avance, annee)` = montant remboursé cette année-là.
- Profil `remboursement_montant_annuel` (ex. 11 200 €) à partir de `remboursement_debut` (ex. 30/06/2029).
- Hypothèse **remboursement intégral** (décision §7.2) : pas d'indexation CA, pas de part non remboursée.
- Cohérence avec l'onglet **Dettes** (restant dû) désormais corrigé (§8).

### 4.3 Base CIR/CII nette par année
Pour un type de crédit `t` (cir/cii) et une année `Y` :
```
baseBrute(Y, t)   = Σ postes(annee=Y, credit_type=t, éligible) . montant
deductions(Y, t)  = Σ aides(credit_cible=t) . quotePartAnnee(aide, Y)
reintegrations(Y, t) = Σ avances(credit_cible=t) . reintegrationAnnee(avance, Y)
baseNette(Y, t)   = max(0, baseBrute(Y, t) − deductions(Y, t) + reintegrations(Y, t))
```
Règle d'éligibilité des postes inchangée (prestation = agréé requis).

### 4.4 Endpoints
- Étendre `GET /api/immobilisations` : renvoyer par immo `basesParAnnee: { "2026": {cir, cii}, ... }` + totaux.
- Sous-CRUD `immobilisation_aides` (POST/PUT/DELETE `.../:id/aides`).
- `postes-disponibles` déjà là ; ajouter le paramètre année (déjà le cas).

## 5. Frontend

- Modale immo : bloc **Période de projet** (début/fin) + bloc **Aides** (ajouter subvention/avance avec leurs
  champs) + postes avec un sélecteur **Année**.
- Vue immo : tableau **base CIR/CII par année** (brute, − aide lissée, + réintégration, = nette).
- Réutiliser le pattern modale/détail existant. Chaque chiffre cliquable → décomposition.

## 6. Cas d'exemple France 2030 (paramètres réels, dossier 4175510)

- Immobilisation : "Outil digital (SaaS) France 2030".
- Projet : **20/02/2026 → 20/02/2028** (24 mois).
- Postes (base éligible, à annualiser sur 2026-2028) — base BPI retenue 316 853 € :
  - Frais de personnel : 177 377 €
  - Frais généraux forfaitaires (20 %) : 35 475 €
  - Sous-traitance "Développement logiciel" : 104 000 € (prestation CII, prestataire agréé)
- Aides :
  - **Subvention 84 000 €** (crédit_cible = cii, définitive) · versée 58 800 € le 15/06/2026 + 25 200 € le 20/02/2028.
  - **Avance récupérable 56 000 €** (crédit_cible = cii) · versée 39 200 € le 15/06/2026 + 16 800 € le 20/02/2028 ·
    remboursement indexé 8,83 % du CA SaaS, profil indicatif 11 200 €/an 2029→2033, plancher 22 400 €.
- Lissage aide totale 140 000 € / 24 mois ≈ 5 833 €/mois :
  - Déduction base CII 2026 ≈ 60 000 € · 2027 ≈ 70 000 € · 2028 ≈ 9 700 €.
- Réintégration avance : 2029→2033 (après le projet), au rythme réel des remboursements.

## 7. Règles confirmées (retour Actemis + Nathan, 23/07/2026)

1. **Réintégration** : les remboursements de l'avance **augmentent la base CII l'année où ils sont effectués**
   (2029→2033), y compris après la fin du projet. → `reintegrationAnnee` ajoutée à la base de l'année de remboursement.
2. **Hypothèse remboursement** : on **part du principe que l'avance est remboursée en totalité**, selon le profil
   indicatif (11 200 €/an, 2029→2033). **Pas** de modélisation de l'indexation CA (8,83 %) ni de la part non remboursée.
   → Simplifie le modèle : pas de champ `remboursement_taux_ca`.
3. **Classification CIR/CII** : portée par un **tag sur chaque dépense (poste)** = `credit_type` (déjà en place, Phase 5.2).
4. **Base fiscale CII ≠ base BPI** : voir §7bis (avis + reco).

## 7bis · Base fiscale CII vs base BPI (corrigé 23/07/2026)

La **base CII fiscale n'est PAS la base BPI (316 853 €)** : la base BPI servait à dimensionner l'aide (fixe désormais),
elle ne sert plus au calcul CII.

**Base CII (art. 244 quater B CGI), depuis le 01/01/2023** :
- dépenses de personnel affectées à la conception,
- dotations d'amortissement des immos créées/acquises affectées,
- sous-traitance à un prestataire **agréé** (sous plafonds spécifiques),
- frais de brevets / dessins et modèles.
- **PAS de forfait de frais de fonctionnement** : le forfait 43 % perso + 75 % amort a été **supprimé pour le CII
  au 01/01/2023** (loi de finances 2022), compensé par la hausse du **taux CII (20 % → 30 % en métropole)**.
- Plafond **400 000 €/an**.

> Le forfait **existe toujours pour le CIR** (désormais **40 % perso + 75 % amort**). La règle dépend donc du tag du poste (cir vs cii).

**Reco Pilot** : base CII = **somme des postes réels tagués CII** (+ dotations d'immo affectées), **sans forfait**.
Le forfait (43/75) ne s'applique qu'aux postes tagués **CIR**. À confirmer Actemis : plafonds sous-traitance, plafond annuel 400 k€, taux.
